## Overview

This project addresses the critical need for an efficient, transparent, and secure student welfare contribution management system at Kabarak University. The previous manual system relied heavily on informal WhatsApp groups and direct student-to-student M-Pesa transfers. This decentralized approach was inefficient, lacked transparency, and posed significant risks of financial mismanagement. 

The **Automated Welfare Management System (WMS)** was developed to streamline the contribution process, enhance accountability, and mitigate the risks associated with peer-to-peer transfers by integrating a centralized M-Pesa payment gateway.

## Technology Stack

The system employs a standard three-tier architectural pattern (presentation, application, data) for maximum scalability and maintainability.

### Frontend (User Interface)
- **Framework:** React 18, Vite
- **Styling:** Tailwind CSS, Ant Design (tailored to Kabarak University's green and maroon color palette)
- **Routing:** React Router DOM
- **HTTP Client:** Axios with interceptors for automatic JWT injection and uniform error handling

### Backend (Application Logic & API)
- **Framework:** Node.js with Express.js
- **Architecture:** RESTful API handling authentication, business logic, and third-party integrations
- **Payment Gateway:** M-Pesa Daraja API (STK Push and asynchronous callbacks)
- **Security:** JWT (JSON Web Tokens) for authentication, bcrypt for password hashing, and strict role-based access control (RBAC)

### Database (Data Tier)
- **Database:** MongoDB (NoSQL document database)
- **ODM:** Mongoose for data modeling and query optimization

## Key Features and Modules

### 1. User Management & Role-Based Access
The system supports two primary roles: Administrator (Admin) and Member (Student). User registration is strictly controlled. The Admin pre-loads student data (admission number, name, faculty, Kabarak University email), and students use their official university email to activate their accounts.

### 2. Contribution Management (M-Pesa Integration)
The core feature of the WMS is its centralized payment collection, which entirely replaces risky direct student-to-student transfers. 
- **STK Push:** Members initiate contributions via the M-Pesa Express (STK Push) prompt directly on their phones.
- **Asynchronous Callbacks:** The backend processes Daraja API callbacks to verify payment completion and automatically updates the database and campaign totals in real time.

### 3. Case Management
This module manages the full lifecycle of a welfare case.
- **Member Submission:** Students can submit requests for assistance along with required supporting documentation (e.g., medical bills).
- **Admin Review:** Administrators review requests against established criteria. Approved cases are published as active fundraising campaigns visible to all members.

### 4. Admin Dashboard & Reporting
Administrators have access to a comprehensive dashboard to:
- Monitor live fund statistics.
- Disburse funds securely to verified recipients.
- Generate large-scale CSV reports on contributions, disbursements, and overall system usage.

## Research & Development Methodology

The project was developed using a mixed-methods action research design, blending Agile and Waterfall methodologies. 

1. **Requirements Elicitation:** Conducted via stakeholder interviews, focus groups, and surveys to understand the exact pain points of the manual WhatsApp-based system.
2. **System Design:** Created comprehensive Use Case Diagrams, Data Flow Diagrams (DFDs), and Entity-Relationship Diagrams (ERDs) to map out data processing and user interaction.
3. **Iterative Implementation:** Development was broken into iterations, starting with core user and contribution management (M-Pesa integration), followed by case management and reporting.
4. **Testing:** Rigorous testing included unit testing (Jest, Mocha/Chai), integration testing, end-to-end testing (Cypress), and User Acceptance Testing (UAT) with real administrators and students.

## Results & Impact

The automated WMS successfully addressed the critical limitations of the previous manual system. Key improvements include:
- **Enhanced Security:** Eliminated direct student-to-student M-Pesa transfers, routing all funds through a centralized, verifiable system.
- **Improved Efficiency:** Automated record-keeping drastically reduced processing times and manual data entry errors.
- **Increased Transparency:** Both students and administrators now have real-time visibility into campaign progress and fund disbursement, fostering greater community trust.

The system serves as a scalable, modern solution tailored specifically to the technological and cultural context of Kenyan higher education.
